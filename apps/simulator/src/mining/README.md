# D01 mining simulator layer

This mining-scoped package is independent of the simulator's existing triathlon
models, generators, Eventstream publisher, and `DEMO_PROFILE`. The repository
root entry point does not re-export mining types. Nothing here starts a hosted
run or publishes to Fabric.

`plant-catalog.json` is the byte-for-byte published D01 metadata asset. Its
SHA-256 and the individually verified authored-asset receipts are recorded in
`catalog-receipt.json`; the metadata preserves the authored module dimensions,
equipment/tag joins, directed stream ports, and the original strict v1 schema.
The catalog is fictional authored parametric geometry and demo assumptions, not
surveyed engineering truth. Its source project is MIT-licensed; see `LICENSE`.
The receipt pins remote GLBs and layout for later UI use without importing the
GPU reconstruction toolchain or copying those assets here.

The v2 numeric and state payload schemas are separate files. The flattened
transport body adds `entityType` (`PlantTelemetry` or `PlantStateEvent`) outside
those strict payloads. `simulator.ts` exposes deterministic 5-second stepping;
callers supply each UTC tick, so offline tests can step without sleeping while
no future or hosted timestamps are generated by a live publisher.
The numeric `quality` enum preserves the pinned v1 values `good`, `uncertain`,
and `bad`; this simulator emits only `good`. Consumers should retain uncertain
and bad observations as structurally valid but exclude them from calculations
that require good-quality samples.

The simulator accumulates one transport batch every 30 simulated seconds
(flushing a final partial batch if a custom duration ends between boundaries).
An unacknowledged batch blocks further steps; retry it with `getPendingBatch()`
and acknowledge its `batch_id` only after successful delivery. This preserves
event IDs and prevents accidental overlapping sends. Alert transition rows ride
beside the transport batch as rows, not as a third `entityType`.
Alert transitions are derived from emitted measurements or observed telemetry
gaps; scripted scenario selection and state transitions are not copied into
alert evidence. Scenario oracles should remain separate from observed data.
